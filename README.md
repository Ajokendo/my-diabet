# Мой диабет

**Сайт:** https://my-diabet.pages.dev/ (Cloudflare Pages). Обновление: Workers & Pages → my-diabet → Create deployment → загрузить zip.

Веб-приложение для конструктора питания и поддержки самоконтроля диабета. Работает без сборки: достаточно открыть `index.html` в браузере.

## Структура

```
index.html            разметка интерфейса
css/app.css           все стили
js/app.js             логика приложения
data/catalog.js       база продуктов и блюд — единственный источник правды
assets/foods/         фото продуктов (по одному файлу на продукт)
core/                 доменная логика: расчёт нутриентов, миграции, семья/устройства
adapters/             хранилище (localStorage), резервные копии, облачная синхронизация
server/               сервер синхронизации (Node.js + PostgreSQL)
new_data/, new_images/  подготовка обновлений; приложением не используются
```

Порядок подключения скриптов: `core/domain.js` → `adapters/runtime.js` → `core/family.js` → `adapters/storage.js` → `adapters/backup.js` → `adapters/cloud.js` → `data/catalog.js` → `js/app.js`.

## База продуктов

Все продукты лежат в `data/catalog.js`, по одной строке на продукт:

```js
{"id":"b79","name":"Гречка варёная","category":"Крупы и гарниры","kcal":92,"c":19.9,"p":3.4,"f":0.6,"fib":2.7,"se":0,"image":"assets/foods/grechka-varenaya.jpg"}
```

- Значения на 100 г: `kcal` — ккал, `c` — углеводы, `p` — белки, `f` — жиры, `fib` — клетчатка (г), `se` — селен (мкг).
- **`id` не меняется никогда.** На него ссылаются меню, избранное и история пользователей. У нового продукта должен быть новый уникальный `id`.
- `category` — одна из категорий каталога (`Крупы и гарниры`, `Мясо и птица`, `Напитки` и т. д.).
- Необязательные поля: `isDish`, `nutritionEstimate`, `brand`, `isShoro`, `composition`, `vitamins`, `minerals`, `source`, `sourceLabel`, `warning`, `note`.

При запуске приложение берёт встроенный каталог из этого файла. В памяти браузера хранятся только продукты, добавленные пользователем. Поэтому для обновления каталога достаточно изменить `data/catalog.js`, патчи в коде не нужны. Если продукт переименован, старое название надо добавить в `CATALOG_RENAMES` в `js/app.js`, чтобы старые меню продолжали на него указывать.

## Стандарт изображений

- JPEG, 512×512, белый фон, продукт целиком по центру, занимает около 80% кадра.
- Без текста, рамок, водяных знаков и элементов интерфейса.
- Имя файла — транслит названия продукта: `assets/foods/grechka-varenaya.jpg`.
- Один продукт — один файл. Чтобы заменить фото, достаточно перезаписать файл с тем же именем.

## Сервер

Для серверной части нужен Node.js 18 или новее. Команды и зависимости определены в `server/package.json`.

```bash
cd server
npm install
npm start
```

Перед запуском настройте параметры окружения и подключение к PostgreSQL. Не добавляйте в репозиторий секреты, реальные медицинские данные и пользовательские базы.

## Фото еды (распознавание)

Экран «📷 Фото еды» отправляет снимки на свой сервер (`server/`), а сервер — в Anthropic API. Ключ API хранится только на сервере.

```bash
cd server
ANTHROPIC_API_KEY=sk-ant-... PHOTO_ACCESS_CODE=придумайте-код node server.js
```

- `ANTHROPIC_MODEL` — модель (по умолчанию `claude-sonnet-5-5`).
- `PHOTO_ACCESS_CODE` — необязательный код; тот же код вводится в приложении в «Настройках сервера», чтобы чужие не тратили ваш ключ.
- В приложении: адрес сервера (по умолчанию `http://localhost:8787`).

Модель только предлагает блюда и вес; углеводы, ХЕ и БЖЕ считаются по базе приложения. Перед добавлением в меню пользователь обязан подтвердить вес.

### Сервер распознавания в Cloudflare (бесплатно, без своего компьютера)

1. Зарегистрируйтесь на dash.cloudflare.com → **Workers & Pages → Create → Worker** → «Hello World» → Deploy.
2. **Edit code** → замените весь код содержимым `server/cloudflare-worker.js` → **Deploy**.
3. **Settings → Variables and Secrets** → добавьте секреты `ANTHROPIC_API_KEY` (ключ с console.anthropic.com) и `PHOTO_ACCESS_CODE` (любой код).
4. В приложении: «Фото еды → Настройки сервера» → адрес `https://<имя>.<аккаунт>.workers.dev` и тот же код доступа.

### Семейная синхронизация (тот же Cloudflare Worker)

1. Cloudflare → **Storage & Databases → D1 → Create database**, имя `my-diabet-db`.
2. Воркер `my-diabet` → **Settings → Bindings → Add binding → D1 database**: имя переменной `DB`, база `my-diabet-db` → Deploy.
3. Код воркера — `server/cloudflare-worker.js` (фото + синхронизация). Таблицы создаются автоматически при первом запросе.

### Переменные, уведомления и лимит фото (v64.23+)

- **Variables (Text, не Secret):** `OWNER_EMAILS` — почта автора (через запятую): его семья распознаёт фото без лимита и видит карточку «Коды для фото»; `FREE_PHOTOS` — бесплатных распознаваний для новой семьи (по умолчанию 10); `PHOTO_CONTACT` — куда писать за кодом.
- **Trigger events → Cron:** каждые 10 минут (`*/10 * * * *`) — уведомление «нет данных с сенсора». Остальные уведомления (низкий, высокий, падает, прогноз) отправляются сразу при приходе данных от xDrip+.
- Ключи Web Push создаются автоматически и хранятся в D1 (таблица `kv`).

В приложении: раздел «Семья». На телефоне пациента — «Это мой дневник → Создать аккаунт», затем «Пригласить» → код. На телефонах родителей — «Я подключаюсь по коду».

Синхронизация по записям: профиль, настройки, меню по дням, замеры глюкозы, активность, анализы, введённый инсулин, расчёты, свои продукты и рецепты. При одновременной правке одной записи остаётся последняя отправленная версия. `server/server.js` (Node) — старый прототип, приложением больше не используется.
